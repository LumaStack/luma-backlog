## ▶ 2026-09-10

measured before capturing: consumers already exists on every bundle and already splits them — ten [project, organization], four [project]. so the wizard's first question is a filter on data that is there today, not new metadata
the design fork is where the SELECTION knowledge lives: a list of questions inside the wizard, which is simple and goes stale as the catalog grows, or a 'adopt me when this is true' field on each bundle, which makes the wizard a reader and offers a new bundle the day it is published
the second is right and costs a format change, so it is a format request rather than something the wizard settles alone
and building it will find holes — there is no coding-best-practices bundle, so the language question has nothing to install for any answer today. the questions somebody wants answered are a better map of what the catalog is missing than a list of bundles somebody thought of
two things it must not become: a questionnaire that installs everything, since INDEX.md's whole posture is 'open a bundle when its line matches the work, and not before'; and a one-time gate, since the second agent arrives months after init and re-running it later is probably the more valuable half
